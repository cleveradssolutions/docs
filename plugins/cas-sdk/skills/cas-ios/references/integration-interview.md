# What to ask the publisher before integrating CAS

Rule zero: never ask for something the project already answers. Read the project first,
state what was found, and ask only to confirm what cannot be read or what changes the
outcome.

## Detect, do not ask

| Fact | Android | iOS |
|---|---|---|
| App identifier | `applicationId` in the app-level Gradle file, per flavour | `PRODUCT_BUNDLE_IDENTIFIER` per target and configuration |
| Language and UI | Kotlin or Java, Views or Compose | Swift or Objective-C, UIKit or SwiftUI |
| Toolchain | `minSdk`, `compileSdk`, AGP, Gradle, Kotlin version | deployment target, Xcode version |
| Dependency manager | `settings.gradle(.kts)`, `dependencyResolutionManagement` | `Podfile` or `Package.swift`, workspace layout |
| Ad SDKs already present | existing AdMob, AppLovin, Unity Ads, ironSource dependencies and their init calls | the same, plus Pods or packages already resolved |
| Consent tooling already present | Google UMP, Didomi, Usercentrics | the same |
| MMP and analytics | AppsFlyer, Adjust, Tenjin, Firebase init sites | the same |
| Where ads would go | activities, fragments, screens, game states | view controllers, SwiftUI scenes |

Report the detected list back in one short block and ask the publisher to correct it.
A wrong guess about the target module or flavour wastes more time than one question.

## Must ask, cannot be derived

1. **CAS ID.** The exact string registered in the CAS platform. **It is not the same thing
   on the two platforms:** on Android it is normally the `applicationId`, on iOS it is the
   App Store id, the number from `apps.apple.com/.../id123456789`. Only the publisher knows
   whether the app is registered and under which id. Without a registered CAS ID the SDK
   serves nothing. Never invent it and never reuse one from a sample.
2. **Is the app already registered in the CAS platform, and is the account manager
   assigned?** If not, integration can proceed, but ads will not serve, and the publisher
   has to finish registration first.
3. **New integration or migration?** If migrating from MAX, LevelPlay or AdMob mediation,
   the previous mediation SDK and its adapters must be removed, not run in parallel.
   Ask which one, and whether ad placements and logic must be preserved as is.
4. **Which ad formats, and where.** Banner, MREC, interstitial, rewarded, app open,
   native. For each: on which screens and at which moments. Rewarded needs the reward
   handler and the server callback decision; app open needs a loading screen story.
5. **Audience.** Is the app directed to children, mixed, or adults only? Child-directed
   apps require the Families solution, `Audience.CHILDREN` before initialization, no
   advertising identifier, and a neutral age screen if the audience is mixed.
6. **Is this a VPN or proxy app?** If yes, the VPN compliant solution is the one to use.
7. **Which solution or adapter set.** Optimal, Families, VPN compliant, or a hand picked
   adapter list. If unsure, the answer is Optimal for a general audience, and the account
   manager decides the rest. At least one solution or adapter is mandatory, the SDK has no
   inventory of its own.
8. **Consent.** Use the built-in CAS consent flow, which is on by default, or an existing
   CMP? If the publisher already has a CMP, the CAS flow must be disabled and privacy
   options set before initialization. Ask where the privacy options button will live.
9. **Advertising identifier.** Should it be collected? Not for children, and not for
   builds that target devices without Google Play services.
10. **AdMob App ID**, if Google demand is used. It must be the identifier generated by the
    CAS system, taken from the CAS UI. A publisher's own AdMob App ID is not valid here.
11. **iOS only: App Tracking Transparency.** Will the app request ATT, with what usage
    description text, and at which moment? This decides the `Info.plist` key and the
    localisation work.
12. **iOS only: SPM or CocoaPods**, if both are possible in the project.
13. **Testing.** Which devices and which build variant will be used for verification, and
    whether the publisher wants test ad mode for the whole debug build or test device ids
    against the live account.
14. **Release.** Who is responsible for turning test mode off, and is there a store
    submission deadline that limits how much of the integration can land now.

## Ask only when relevant

- Build variants, flavours or schemes with different application ids: each one is a
  separate CAS ID and has to be registered separately.
- Integration into a library module instead of the app module: `casId` must then be set
  explicitly.
- Impression level data needed for analytics or a revenue dashboard.
- In-app purchases to be reported to CAS.
- Minimum interval between interstitials, banner refresh interval, autoload behaviour.
- Existing mediation reports that the publisher wants to keep comparable after migration.
