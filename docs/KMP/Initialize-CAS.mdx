---
title: Initialize CAS SDK
---

Before loading ads, have your app initialize the CAS Mobile Ads SDK by calling `CASMobileAds.initialize()`.
The call returns immediately and reports the result through a `CASInitializationListener`.

The `casId` is a unique identifier for the CAS content registered for your app on each platform.

```kotlin
import com.cleveradssolutions.plugin.kmp.CASInitializationListener
import com.cleveradssolutions.plugin.kmp.CASMobileAds

fun initializeAds(context: Any?) {
    CASMobileAds.initialize(
        // Android: an Activity, Application or any other Context. iOS: pass null.
        context = context,
        casId = "APP CAS ID",
        listener = CASInitializationListener { config ->
            if (config.error != null) {
                println("CAS Mobile Ads SDK initialization failed: ${config.error}")
            } else {
                println("CAS Mobile Ads SDK initialized in ${config.countryCode} country")
            }
        },
    )
}
```

<Warning>
The CAS ID is **different on each platform**, so shared code cannot use a single literal. Declare it per
platform as shown below.
</Warning>

## The CAS ID of each platform
On Android the CAS ID is your application package name, on iOS it is your App Store ID. Declare it with an
`expect` property so that common code stays platform agnostic:

```kotlin
// commonMain
expect val casId: String

// androidMain
actual val casId: String = "com.yourcompany.yourproject"

// iosMain
actual val casId: String = "123456789"
```

```kotlin
CASMobileAds.initialize(
    context = context,
    casId = casId, // [!code highlight]
)
```

<AccordionGroup>
<Accordion title="What is CAS ID on Android?">

In most cases, a `casId` is the same as your application package name.
- A [package name](https://developer.android.com/studio/build/application-id) uniquely identifies your app on the device and in the Google Play Store.
- The package name value is case-sensitive and is often referred to as an `APPLICATION_ID`.
- Find your app's package name in your module (app-level) Gradle file, usually `shared/build.gradle.kts` (example package name: `com.yourcompany.yourproject`).

You can read it from `BuildConfig` instead of hardcoding it:
```kotlin
// androidMain
actual val casId: String = BuildConfig.APPLICATION_ID
```

</Accordion>
<Accordion title="What is CAS ID on iOS?">

In most cases, a CAS ID is the same as your app store ID.
You can find an app store ID in the URL of your app’s Apple App Store URL. For example, if the URL is
`apps.apple.com/us/app/id123456789` then the app store ID is `123456789`.

</Accordion>
<Accordion title="I have not registered an app yet">

If you haven't created a CAS account and registered an app yet, now's a great time to do so at https://cas.ai

To experiment before that, use the demo CAS ID, which always serves test ads on every device:
```kotlin
CASMobileAds.initialize(
    context = context,
    casId = CASMobileAds.TEST_ID, // [!code highlight]
)
```

See [Enable test ads](KMP/Enabling-test-ads) for the other ways to test safely.

</Accordion>
</AccordionGroup>

The `context` parameter is only used on Android. On iOS the value is ignored, so shared code can pass the
platform context it already has without branching.

<AccordionGroup>
<Accordion title="Where does the context come from?">

On Android, pass the `Activity` or `Application` you already have:
```kotlin
// androidMain
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent { App(context = this) }
    }
}
```

On iOS, there is no context to pass:
```kotlin
// iosMain
fun MainViewController() = ComposeUIViewController {
    App(context = null)
}
```

</Accordion>
</AccordionGroup>

If `initialize()` is not called, the first ad load automatically initializes the CAS Mobile Ads SDK with the
CAS ID defined in the ad instance arguments.

If an error occurs, the SDK will attempt automatic reinitialization internally. However, the listener will not
be invoked again with a subsequent result. For the most up-to-date result, call `initialize()` again at a later time.

You can check whether initialization has already completed:
```kotlin
val isReady: Boolean = CASMobileAds.isInitialized
```

<Error>
Do not initialize mediated advertising SDKs (CAS does that for you).
Not following this step will result in noticeable integration issues.
</Error>

## Initialization result
`CASInitializationResult` carries everything the SDK learned during initialization.

<Property name="error" type="String?">
Error message if initialization failed, or `null` if initialization completed successfully.
</Property>
<Property name="countryCode" type="String?">
Country code detected during initialization, if available.
</Property>
<Property name="isConsentRequired" type="Boolean">
Indicates whether consent is required for the user.
</Property>
<Property name="consentFlowStatus" type="CASConsentFlowStatus">
Current consent flow status.
</Property>

## Automatic user consent flow
To get consent for collecting personal data of your users, we suggest you use a built-in Consent Flow, which comes with
a pre-made consent form that you can easily present to your users. That means you no longer need to create your own consent window.

The user will see the consent flow when your app initializes the CAS SDK.
Once the user completes the flow, the initialization listener is invoked.

You can choose whether to `showConsentFormIfRequired` in the arguments of `initialize()`:
```kotlin
CASMobileAds.initialize(
    context = context,
    casId = casId,
    showConsentFormIfRequired = true, // [!code highlight]
    listener = CASInitializationListener { config ->
        if (config.consentFlowStatus == CASConsentFlowStatus.OBTAINED) {
            println("CAS Mobile Ads SDK obtain user consent")
        }
    },
)
```

You must wait until the user finishes the consent flow before you initialize third-party SDKs (such as MMPs or analytics SDKs). For this reason, initialize such SDKs from within your initialization-completion callback. If you were to initialize these third-party SDKs before the user completes the consent flow, these third-party SDKs would not be able to access relevant identifiers and you would suffer a material impact on measurement, reporting, and ad revenue.

<Info>
Read more about "Privacy options button" and "Debug geography" on the [CAS User Consent Flow page](KMP/User-Consent-Flow)
</Info>

## Always test with test ads
When building and testing your apps, make sure you use test ads rather than live, production ads. Failure to do so can lead to suspension of your account.

By default, CAS initializes mediation in live mode. To enable test ad mode, set `forceTestAds` in the arguments of `initialize()`:
```kotlin
CASMobileAds.initialize(
    context = context,
    casId = casId,
    forceTestAds = true, // [!code highlight]
    testDeviceIds = setOf(
        "Your test device ID", // [!code highlight]
    ),
    listener = null,
)
```

You can also test in a release build by registering your device as a test device. Check the logs for your device's ID value.

For more information about how the CAS.AI SDK's test ads work, see [Enable test ads](KMP/Enabling-test-ads)

## Prohibition on Personal Information from Children
Apps can be marked as child-directed or [Children’s Online Privacy Protection Act (COPPA)](https://www.ftc.gov/tips-advice/business-center/privacy-and-security/children%27s-privacy) applicable through the CAS UI.

If the app has knowledge of specific individuals as being COPPA-applicable, it should make use of the `targetAudience` parameter in `initialize()`.
```kotlin
CASMobileAds.initialize(
    context = context,
    casId = casId,
    targetAudience = CASTaggedAudience.NOT_CHILDREN, // [!code highlight]
    listener = null,
)
```

Available values are `CASTaggedAudience.UNDEFINED`, `CASTaggedAudience.CHILDREN` and `CASTaggedAudience.NOT_CHILDREN`.

If your app targets both children and older users, all ads that may be shown to children must comply with COPPA.
To ensure compliance, a **neutral age screen** must be implemented so that ads unsuitable for children are only shown to appropriate audiences.
A neutral age screen is a tool—such as an age gate—that verifies a user’s age without encouraging them to misrepresent it, and prevents children from accessing content not intended for them.

## (Optional) Mediation extras
Additional key-value settings passed to the mediation networks.
```kotlin
CASMobileAds.initialize(
    context = context,
    casId = casId,
    mediationExtras = mapOf("key" to "value"), // [!code highlight]
    listener = null,
)
```

## (Optional) Retrieve the Version Number
To programmatically retrieve the SDK version number at runtime, CAS provides the following property:
```kotlin
val sdkVersion: String = CASMobileAds.sdkVersion
```

## (Optional) Debug logging
The enabled Debug Mode will display a lot of useful information for debugging about the states of the SDK
with the tag `CAS`. Disabling Debug Mode may improve application performance. Disabled by default.
```kotlin
CASMobileAds.debugLoggingEnabled = true
```

## (Optional) Trial ad-free interval
Defines the time interval, in seconds, starting from the moment of the initial app installation, during which users can use the application without ads being displayed while still retaining access to the Rewarded Ads format. Within this interval, users enjoy privileged access to the application's features without intrusive advertisements.

```kotlin
val secondsIn7Days = 604800
CASMobileAds.trialAdFreeInterval = secondsIn7Days
```
