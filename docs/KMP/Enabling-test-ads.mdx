---
title: Enabling test ads
description: This guide explains how to enable test ads in your ads integration.
---

It's important to enable test ads during development so that you can click on them without charging CAS advertisers.

<Error>
We strongly suggest that you enable test ads mode when you validate the integration. If you click on too many ads without being in test mode, you risk your account being flagged for invalid activity.
</Error>

There are two ways to get test ads:
- [Enable test ad mode](KMP/Enabling-test-ads#enable-test-ad-mode) for all devices.
- [Set device ids to test ad](KMP/Enabling-test-ads#enable-test-devices).

Ads with Test Ads mode are safe to click. Requests, impressions, and clicks on test ads will not show up in your account's reports.
Test full-screen ads display details of the CAS integration and tips for solving errors. Go to the Mediation Adapters section to make sure that the advertising networks you want are integrated correctly.

## Enable Debug log mode
The enabled Debug Mode will display a lot of useful information for debugging about the states of the SDK with log tag `CAS`.
Disabled by default. Disabling Debug Mode may improve application performance.
```kotlin
CASMobileAds.debugLoggingEnabled = true
```

On Android the output goes to Logcat, on iOS to the Xcode console.

<Info>
If you have discovered a problem in the work of the SDK, please provide us with a description of the problem along with the full log of your device.
</Info>

## Enable test ad mode
The quickest way to enable testing is to use test ad mode. Test ad mode is not associated with your CAS account, so there's no risk of your account generating invalid traffic when using it.

The easiest way to load test ads is to use the demo CAS ID:
```kotlin
CASMobileAds.initialize(
    context = context,
    casId = CASMobileAds.TEST_ID, // [!code highlight]
)
```

You can also keep your own CAS ID and force test ads:
```kotlin
CASMobileAds.initialize(
    context = context,
    casId = casId,
    forceTestAds = true, // [!code highlight]
)
```

To enable it for debug builds only, pass your own build flag from each platform. One way is an `expect`
declaration in your shared module:
```kotlin
// commonMain
expect val isDebugBuild: Boolean

// androidMain
actual val isDebugBuild: Boolean = BuildConfig.DEBUG

// iosMain
actual val isDebugBuild: Boolean = Platform.isDebugBinary
```

```kotlin
CASMobileAds.initialize(
    context = context,
    casId = casId,
    forceTestAds = isDebugBuild, // [!code highlight]
)
```

## Enable test devices
If you want to do more rigorous testing with production-looking ads, you can configure your device as a test device and use your own manager id. Test devices can be added programmatically.

Follow the steps below to add your device as a test device.
1. Run an app configured with the CAS on device.
2. Check the log output for a message that looks like this:
```
To get test ads on this device, set "12345678901234567890123456789012"
```
3. Copy your alphanumeric test device ID to your clipboard.
4. Modify your code to set the test device ID through `testDeviceIds` before CAS initialization.
```kotlin
CASMobileAds.initialize(
    context = context,
    casId = casId,
    testDeviceIds = setOf("12345678901234567890123456789012"), // [!code highlight]
)
```
<Info>
Be sure to remove the code that sets these test devices before you release your app.
</Info>

5. Re-run your app.
6. Well done, ads on this device are safe to click. Requests, impressions, and clicks on ads in test mode will not show up in your account's reports.
