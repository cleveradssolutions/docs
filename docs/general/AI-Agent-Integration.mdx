You can hand a CAS.AI integration to an AI coding agent. This page is for both of you: it
tells you what to expect, and it tells the agent what it is not allowed to do.

<Error>
The one rule that cannot be broken: **every build that is not a release build must run
[test ads](Android/Enabling-test-ads)**. Clicking a live ad during development is invalid
traffic and can get your account flagged. No integration is worth that.
</Error>

## The documentation, for agents

The whole documentation is published in a form agents read directly, without rendering the
site:

| File | What it is |
| ---- | ---------- |
| [llms.txt](https://docs.page/cleveradssolutions/docs/llms.txt) | An index of every page with a one-line description. Small, fetch this first. |
| [llms-full.txt](https://docs.page/cleveradssolutions/docs/llms-full.txt) | The full text of every page in one file. Large, roughly a quarter of a million tokens. |

<Info>
Point your agent at `llms.txt` and let it fetch the pages it needs. Pasting
`llms-full.txt` into a prompt wastes context on eight platforms you are not using.
</Info>

## Agent skills

The documentation answers *where it is written*. A skill answers *in what order to do it,
what to ask you first, and what never to do*. We publish skills for Android and iOS in the
[documentation repository](https://github.com/cleveradssolutions/docs/tree/master/plugins).

<CodeGroup>
```bash Any agent
npx skills add cleveradssolutions/docs/plugins/cas-sdk/skills
```

```bash Claude Code
/plugin marketplace add cleveradssolutions/docs
/plugin install cas-sdk@cas-skills
```

```text By hand
Point the agent at the skill folder for your platform:

plugins/cas-sdk/skills/cas-android/SKILL.md
plugins/cas-sdk/skills/cas-ios/SKILL.md
plugins/cas-sdk/skills/cas-flutter/SKILL.md
plugins/cas-sdk/skills/cas-react-native/SKILL.md
plugins/cas-sdk/skills/cas-kmp/SKILL.md
plugins/cas-sdk/skills/cas-unreal/SKILL.md
plugins/cas-sdk/skills/cas-cordova/SKILL.md

Each folder is plain Markdown and is self contained.
```
</CodeGroup>

The first command uses the open [skills CLI](https://github.com/vercel-labs/skills), which
detects the agents installed on your machine and copies the skills into each one. It
supports Claude Code, Codex, Cursor, OpenCode and many others, and needs Node.js only to
run the installer. Add `--skill cas-android` for one platform, and update later with
`npx skills update`.

| Skill | What it does | Sample prompt |
| ----- | ------------ | ------------- |
| `cas-android` | Adds the SDK to a native Android app: Gradle setup, ad networks, initialization, consent, ad formats, verification on test ads. | *Add CAS.AI banner and interstitial ads to this app* |
| `cas-ios` | The same for a native iOS app, with Swift Package Manager or CocoaPods and the `Info.plist` configuration. | *Integrate CAS.AI into my iOS app and show a rewarded ad* |
| `cas-flutter` | The `clever_ads_solutions` package, the CAS Gradle plugin on Android and the `casconfig.rb` script on iOS, then the Dart ad formats. | *Add CAS.AI ads to my Flutter app* |
| `cas-react-native` | A React Native or Expo app: the `react-native-cas` package, the Expo config plugin or the bare native setup, then the TypeScript ad formats. | *Add CAS.AI ads to my React Native app* |
| `cas-kmp` | A Kotlin Multiplatform app: the `cas-kmp` library in `commonMain`, the CAS Gradle plugin on Android and the CAS Swift Package on iOS, then the shared ad formats and the Compose composables. | *Add CAS.AI ads to my Kotlin Multiplatform app* |
| `cas-unreal` | An Unreal Engine project: the CAS-Unreal plugin, the `CleverAdsSolutions` module, the per-platform CAS.AI Config window and the packaging prerequisites, then the C++ or Blueprint ad formats. | *Add CAS.AI rewarded ads to my Unreal game* |
| `cas-cordova` | A Cordova or Ionic app: the `cordova-plugin-casai` plugin and its `config.xml` variables, then the JavaScript ad formats with their Promise and document-event APIs. | *Add CAS.AI ads to my Ionic app* |

<Info>
The skills are not Claude specific. `SKILL.md` is Markdown with a small header, and the
files it links to sit next to it. `AGENTS.md` in the repository root explains how to use
them from any other agent.
</Info>

Unity, the CAS Publishing Hub and the studio Firebase setup have their own agent guides in
the same repository, under `llm-guides/`. A Unity project belongs to those, not to the
Android and iOS skills.

<Info>
Because the agent clones the repository, it gets this documentation with the skill. A good
agent reads the page from its working copy instead of fetching the site, and quotes the
page rather than keeping its own copy of the integration code.
</Info>

## What the agent should ask you

A good integration starts with questions, not with code. Expect to be asked, and have the
answers ready:

- **Your CAS ID.** On Android it is normally the `applicationId`. On iOS it is the App
  Store id, the number from `apps.apple.com/.../id123456789`, not the bundle identifier.
- **Whether the app is registered** in the CAS dashboard.
- **New integration or a migration** from another mediation, and which one.
- **Which ad formats, and on which screens.**
- **Your audience:** child-directed, mixed, or adults only, and whether the app provides
  VPN or proxy services. This decides which solution is allowed.
- **Which solution:** Optimal, Families, VPN Compliant, or a hand-picked adapter list.
- **Consent:** our built-in flow, or a consent platform you already use.
- **iOS:** App Tracking Transparency, whether the app asks and with what text.
- **How it will be tested**, on which device and which build.

Anything the agent can read from your project, such as the minimum SDK version, the
dependency manager or the language, it should read rather than ask.

## Rules for the agent

These hold whichever agent you use, and whether or not it loaded our skill.

<Warning>
**Identifiers are never invented.** The CAS ID, the AdMob App ID and test device ids come
from the CAS dashboard or from you. An identifier copied from a sample app belongs to
someone else's account.
</Warning>

<Warning>
**CAS initializes the mediated ad networks.** The app must not call an ad network
initializer, and must not add network or adapter dependencies by hand. See
[Initialize CAS SDK](Android/Initialize-CAS).
</Warning>

Also, in short:

- No ad request before initialization completes, and no analytics or attribution SDK
  started before the [consent flow](Android/User-Consent-Flow) finishes.
- No `load()` call from inside a failure callback.
- Every ad instance is destroyed, on Android, or released, on iOS, with the screen that
  owns it.
- No personal data in targeting, and no location collection that exists only to serve ads.
- On iOS, the `Info.plist` ad network identifiers are written by our configuration script
  and re-run on every SDK update, never edited or trimmed by hand.
- No application id, bundle id, dependency version or deployment target changed silently
  to make a build pass.
- Store privacy disclosures, the ATT text and the decision about a child-directed audience
  are yours, not the agent's.

## Where ads belong

The agent should propose a placement and let you correct it, not place ads wherever the
code is easiest to change:

- **Interstitial:** loaded when the screen that shows it is created, shown on a transition
  the user is already making, such as a finished level or a closed screen. Never in the
  middle of a task.
- **Rewarded:** loaded early, shown only from a button the user pressed, with the reward
  stated before the press and granted on the reward callback, not when the ad is closed.
- **Banner:** in a fixed container at the top or the bottom, outside the scrolling content,
  never over a button, a navigation bar or game controls, with the height reserved so the
  layout does not jump.
- **App open:** only on a return to the app, or on a cold start while a loading screen is
  still up.
- **Native:** inside your own layout, marked as an ad, spaced so two are never on screen
  together.

<Warning>
An ad over a control earns accidental clicks, and accidental clicks are invalid traffic.
A misplaced ad costs more than no ad.
</Warning>

## What "done" means

Ask for evidence, not a summary. An integration is finished when the project builds, the
SDK initializes without an error, and a **test ad loads and is shown for every format that
was added**, with the log to prove it. A test full-screen ad also lists the mediation
adapters that initialized correctly, which is the fastest way to confirm the ad network
set is right.

<Warning>
Before you publish: test ad mode off, test device ids removed, debug logging off. See
[Enabling test ads](Android/Enabling-test-ads).
</Warning>
