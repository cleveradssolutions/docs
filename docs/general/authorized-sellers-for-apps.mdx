[app-ads.txt](https://iabtechlab.com/wp-content/uploads/2019/03/app-ads.txt-v1.0-final-.pdf) is a vital text file that app developers upload to their websites, listing the ad sources authorized to sell their inventory. Similar to the web, the IAB has established a system that enables buyers to verify who is permitted to buy and sell specific in-app ad inventory. This initiative plays a crucial role in combating fraud and enhancing transparency and efficiency across the ecosystem. Consequently, most savvy brand marketers and demand-side platforms (DSPs) tend to avoid purchasing inventory without app-ads.txt implementation.

## How app-ads.txt Works for Mobile Apps

When a DSP seeks to bid on app inventory, it follows a chain of checks:

1. The app's store listing points to the **developer website**.
2. The DSP reads `app-ads.txt` from the root of that website.
3. The file contains the CAS.AI seller line for your account: `cas.ai, <your seller ID>, DIRECT`.
4. The same seller ID is listed in [cas.ai/sellers.json](https://cas.ai/sellers.json).

The DSP will only accept bid requests from the ad sources listed in this file. If any link of the chain is broken, your impressions are bought at a lower price or not bought at all.

## Benefits of Implementing app-ads.txt for Your Mobile App

1. **Attract Brand Budgets**  
   Major brands and agencies are more inclined to purchase app inventory through DSPs that verify authorized ad sources. By implementing app-ads.txt, developers signal to DSPs that their inventory is secure. Those who neglect to adopt app-ads.txt risk exclusion from DSPs' targeted media pools.

2. **Combat Ad Fraud**  
   Malicious actors may create counterfeit apps that impersonate legitimate ones, misleading DSPs into spending brand budgets on fraudulent inventory. This not only harms legitimate developers but also deprives them of revenue intended for their apps. Implementing app-ads.txt helps prevent unauthorized impersonation and minimizes instances of fraud, ultimately safeguarding developers’ financial interests.

<Warning>
Failing to implement app-ads.txt could negatively impact your eCPMs, as fewer advertisers may be willing to engage with your app.  
If you manage multiple domains, ensure that all relevant domains are updated accordingly.
</Warning>

## Get your app-ads.txt file

Each developer account has its own app-ads.txt file in the [CAS.AI dashboard](https://platform.cas.ai). The file is built from three parts:
- The entries of all CAS.AI mediation partners, maintained by the CAS.AI team.
- Your personal seller line `cas.ai, <your seller ID>, DIRECT`, linked to your record in sellers.json.
- Additional lines for your account, if your account manager added any.

To find the file:

<Steps>
<Step title="Open Applications">
Open **Applications** in the [CAS.AI dashboard](https://platform.cas.ai).
</Step>
<Step title="Open the app-ads.txt window">
Click the status in the **APP-ADS** column of your app.
</Step>
<Step title="Get the file">
In the app-ads.txt window, use **Download app-ads.txt** or **Copy all**.

</Step>
</Steps>

## Choose your developer website

The **Developer Website** in your store listing tells ad networks where to look for app-ads.txt. You have two options.

<Tabs>
<TabItem label="Your own website" value="own">

<Steps>
<Step title="Download the file">
Download your app-ads.txt from the dashboard.
</Step>
<Step title="Upload it to your website">
Place it at the root of your website: `https://example.com/app-ads.txt`.  
If you already have an app-ads.txt with other ad sources, add the CAS.AI lines to it and keep the rest.
</Step>
<Step title="Set it in the store listing">
Set your website as the **Developer Website** of every app in the store listing.
</Step>
</Steps>

<Warning>
You are responsible for keeping the file up to date. When CAS.AI adds partners or changes lines, the app status changes to **Missing** until you update the file on your website. Check the dashboard regularly.
</Warning>

</TabItem>
<TabItem label="CAS.AI developer page" value="landing">

CAS.AI creates a developer page for you on your own subdomain, like `vXXXXXXXX.cas-apps.com`. The page already serves your app-ads.txt and redirects visitors to your developer page in the store.

<Steps>
<Step title="Copy the developer page">
In the app-ads.txt window, click **Copy developer page**.
</Step>
<Step title="Set it in the store listing">
Set the copied address as the **Developer Website** of every app in the store listing, as described [below](#updating-a-developer-website).
</Step>
</Steps>

That is all. The file on the developer page is always up to date: CAS.AI updates it every time the list of partners changes.

</TabItem>
</Tabs>

<Warning>
Do not use a website you don't own, or a website shared with other developers, as your Developer Website. Ad networks cannot link such a website to your account, and your account is not listed in sellers.json.
</Warning>

## Check the status in the dashboard

CAS.AI checks app-ads.txt of every app once a day. It finds your app in the store, reads the Developer Website from the store listing and compares the app-ads.txt on that website with your file in the dashboard. If your own website is in the store listing, the file on your website is checked, not the one on the developer page.

The result is shown in the **APP-ADS** column of **Applications**. Use the **All app-ads** filter to show all apps with problems at once.

| Status | Meaning | What to do |
|---|---|---|
| **OK** | The file is found and has all required lines. | Nothing. |
| **Not checked yet** | The app has not been checked yet. | Wait for the next daily check. |
| **Missing** | The file is found, but some lines are missing. The app-ads.txt window lists them. | Add the missing lines to the file on your website, or switch to the CAS.AI developer page, where the file is always complete. |
| **Issue** | The store listing has no Developer Website, or the website does not return the file. | Set the Developer Website in the store listing. If it is set, make sure `https://<your website>/app-ads.txt` opens in a browser. |
| **Old domain** | The store listing points to a CAS.AI website that is no longer used for app-ads.txt. | Replace the Developer Website with your CAS.AI developer page. |
| **No store** | The app is not found in the store. | When the app is back in the store, click **Recheck** in the app-ads.txt window. |

After fixing the problem, click **Recheck** in the app-ads.txt window to check the app without waiting for the daily check.

<Info>
After you change the Developer Website, the store needs time to update the listing, and the status does not change until it does. Ad networks also need time to crawl the new file: AdMob, for example, may take up to 24 hours.
</Info>

## Updating a Developer Website
It is important to pay attention to the instructions below before beginning the app-ads.txt implementation.
- You must list your **Developer Website URL** in the App Store and Google Play, as relevant.
- There must be a valid developer website URL in all app stores hosting your apps.
- This app-ads.txt guide only addresses Apple's App Store and Google Play stores, with both you can fully comply with the specs of app-ads.txt.
- The Developer Website URL is used by advertising platforms to locate the app-ads.txt file. Only the host name is used: you don't need to put the full file URL in the store listing.

## Ensure your app-ads.txt files can be crawled
If you host the file on your own website, work through the following troubleshooting steps. The CAS.AI developer page already meets all of them.

<Info>
The following information was taken from a [Google Support resource](https://support.google.com/admob/answer/9679128).
</Info>

### Confirm that the file is reachable from the root domain
Redirects from `domain.com/app-ads.txt` to `www.domain.com/app-ads.txt` are fairly common. App-ads.txt crawling will start at the root domain. The root domain needs to return from, or redirect to, the app-ads.txt file.  

<Warning>
An app-ads.txt file on `www.domain.com/app-ads.txt` will only be crawled if `domain.com/app-ads.txt` redirects to it.
</Warning>

### Confirm the file is not temporarily unavailable
If a previously seen app-ads.txt file is unavailable on a subsequent re-crawl, the previously seen entries will be:
- Purged if the response is a hard 404 error (page that actually doesn’t exist; HTTP 404 status).
- Retained for up to five days if the response is a soft 404 error (a real page returned for a URL that doesn't actually exist; HTTP 200 status) or a 500 server error.

### Ensure file is returned with an HTTP 200 OK status code
While a request for an app-ads.txt file may return the contents of the file in the response body, if the status code in the response header indicates the file was not found (e.g., status code 404):
- The response will be ignored.
- The file will be considered non-existent.  

Make sure the file has an HTTP 200 OK status code.

### Ensure there are no formatting errors or invalid characters in the file
Formatting errors, such as invalid whitespace characters, may be difficult to detect but can make an app-ads.txt file difficult to parse by a crawler, and may therefore result in a file being ignored. Avoid copying and pasting app-ads.txt entries from a rich text editor; we recommend a plain text editor. You can also check for invalid UTF-8 characters in your app-ads.txt file using a HEX editor. 

Each line has the format defined by the IAB:
```
<ad source domain>, <publisher account ID>, <DIRECT or RESELLER>[, <certification authority ID>]
```
Everything after `#` is a comment. To check the upload, open `https://<your website>/app-ads.txt` in a browser: if the content is displayed, crawlers will most likely find it too.
