title: Purchase Info
---

The `PurchaseInfo` class is used to report in-app purchases to CAS.AI. Along with the SDK's ad revenue tracking, this allows you to get a complete picture of a user's total value by combining ad revenue and IAP revenue in one place.

The total reported revenue is calculated as:

```
revenue = quantity * price * currency_rate
```

## Reporting a purchase

Call `CAS.reportPurchase(_:)` with a `PurchaseInfo` object as soon as you've confirmed a completed transaction. This feeds IAP revenue into CAS.AI alongside your ad revenue.

<Info>
`PurchaseInfo` is exposed to Objective-C as `CASPurchaseInfo`.
</Info>

Where you call it depends on which StoreKit version you use:
- **StoreKit 2 (Swift):** inside your `Transaction.updates` listener, right after you verify the transaction. This is typically also where you'd call `transaction.finish()`.
- **StoreKit 1 (Objective-C):** inside your `SKPaymentTransactionObserver`'s `paymentQueue:updatedTransactions:` delegate method, in the `SKPaymentTransactionStatePurchased` case. This is typically also where you'd call `finishTransaction:`.

### 1. Create `PurchaseInfo`

Build the object from the transaction's product ID, price, currency, and quantity.

<CodeGroup synchronize="true">
```swift SK2 (Swift)
// Inside your Transaction.updates listener
func listenForTransactions() -> Task<Void, Error> {
    Task.detached {
        for await result in Transaction.updates {
            guard let transaction = try? self.verify(result) else { continue }

            let purchaseInfo = PurchaseInfo(
                productID: transaction.productID,
                price: transaction.price ?? 0,
                currency: transaction.currency?.identifier,
                quantity: transaction.purchasedQuantity
            )

            // See steps 2-4 below, then call CAS.reportPurchase(purchaseInfo)

            await transaction.finish()
        }
    }
}
```

```objc SK1 (Objective-C)
// Inside your SKPaymentTransactionObserver
- (void)paymentQueue:(SKPaymentQueue *)queue
 updatedTransactions:(NSArray<SKPaymentTransaction *> *)transactions {
    for (SKPaymentTransaction *transaction in transactions) {
        if (transaction.transactionState != SKPaymentTransactionStatePurchased) {
            continue;
        }

        CASPurchaseInfo *purchaseInfo = [[CASPurchaseInfo alloc]
            initWithProductID:transaction.payment.productIdentifier
                        price:product.price
                     currency:product.priceLocale.currencyCode
                     quantity:transaction.payment.quantity];

        // See steps 2-4 below, then call [CAS reportPurchase:purchaseInfo]

        [queue finishTransaction:transaction];
    }
}
```
</CodeGroup>

### 2. Recommended: attach validation data

Add the transaction's validation info so CAS.AI can verify the purchase server-side.

<CodeGroup synchronize="true">
```swift SK2 (Swift)
purchaseInfo.addValidation(
    transactionID: transaction.id,
    jwsRepresentation: result.jwsRepresentation
)
```

```objc SK1 (Objective-C)
NSURL *receiptURL = [[NSBundle mainBundle] appStoreReceiptURL];
NSData *receiptData = [NSData dataWithContentsOfURL:receiptURL];

[purchaseInfo addValidationWithTransactionID:transaction.transactionIdentifier
                                  receiptData:receiptData];
```
</CodeGroup>

### 3. If the product is a subscription, also call `addSubscription`

StoreKit doesn't hand you a ready-made "is this a subscription" flag on the transaction itself. That comes from your own product catalog (e.g. the `Product.ProductType` you fetched when listing products, or however you classify product IDs on your side). Check that first, then attach the subscription data:

<CodeGroup synchronize="true">
```swift SK2 (Swift)
// Determine this from your product catalog, e.g. product.type == .autoRenewable
let isSubscription: Bool = MyStore.isSubscription(transaction.productID)

if isSubscription {
    purchaseInfo.addSubscription(
        originalID: transaction.originalID,
        originalPurchaseDate: transaction.originalPurchaseDate,
        jsonRepresentation: transaction.jsonRepresentation
    )
}
```

```objc SK1 (Objective-C)
// Determine this from your product catalog
BOOL isSubscription = [MyStore isSubscriptionProductID:transaction.payment.productIdentifier];

if (isSubscription) {
    [purchaseInfo addSubscriptionFromStoreKit];
}
```
</CodeGroup>

<Info>
`addSubscriptionFromStoreKit` requires iOS 16.0+ and pulls the subscription data automatically from `Transaction.currentEntitlement`.
</Info>

### 4. Report

With the product info, validation, and (if applicable) subscription data attached, `purchaseInfo` is ready to send:

<CodeGroup synchronize="true">
```swift SK2 (Swift)
CAS.reportPurchase(purchaseInfo)
```

```objc SK1 (Objective-C)
[CAS reportPurchase:purchaseInfo];
```
</CodeGroup>

## Automatic forwarding to Tenjin
 
Purchases reported through `CAS.reportPurchase(_:)` can also be forwarded automatically to Tenjin Analytics, so you don't need a separate integration to get IAP revenue into Tenjin.
 
<Info>
This requires CAS SDK 4.8.1 or higher, and the feature must be enabled for your account. Contact your account manager to request it.
</Info>
