---
title: Purchase Info
description: Report in-app purchases to CAS.AI to combine IAP revenue with ad revenue and track a user's total value.
---

The `PurchaseInfo` class is used to report in-app purchases to CAS.AI. Along with the SDK's ad revenue tracking, this allows you to get a complete picture of a user's total value by combining ad revenue and IAP revenue in one place.
The total reported revenue is calculated as:

```
revenue = quantity * price * currency_rate
```

## Reporting a purchase
Call `CAS.reportPurchase(...)` with a `PurchaseInfo` object as soon as you've confirmed a completed transaction. This feeds IAP revenue into CAS.AI alongside your ad revenue.
For Google Play Billing, report the purchase after it has been successfully completed and verified.

### 1. Create `PurchaseInfo`
Build the object from the purchase's product ID, price, currency, and quantity.

<CodeGroup synchronize={true}>
```kotlin
val purchaseInfo = PurchaseInfo(
    productId = purchase.products[0],
    price = price,
    currency = currency,
    quantity = purchase.quantity
)
```

```java
PurchaseInfo purchaseInfo = new PurchaseInfo(
    purchase.getProducts().get(0),
    price,
    currency,
    purchase.getQuantity()
);
```
</CodeGroup>

| Parameter | Description |
| --- | --- |
| `productId` | Product identifier from the IAP provider. |
| `price` | Price of one purchased item in the selected currency. |
| `currency` | ISO 4217 currency code, for example `USD` or `EUR`. |
| `quantity` | Number of items being purchased. Must be at least `1`. |

### 2. Recommended: attach validation data
For Google Play purchases, pass the original purchase JSON and signature so CAS.AI can verify the purchase server-side.

<CodeGroup synchronize={true}>
```kotlin
purchaseInfo.setValidation(
    purchase.originalJson,
    purchase.signature
)
```

```java
purchaseInfo.setValidation(
    purchase.getOriginalJson(),
    purchase.getSignature()
);
```
</CodeGroup>

<Info>
Validation data is optional, but it is recommended when available.
</Info>

### 3. If the product is a subscription
For Google Play subscriptions (`BillingClient.ProductType.SUBS`), use `setSubsValidation` instead of `setValidation`. It additionally takes the purchase token and the subscription purchase time.

<CodeGroup synchronize={true}>
```kotlin
purchaseInfo.setSubsValidation(
    purchase.originalJson,
    purchase.signature,
    purchase.purchaseToken,
    purchase.purchaseTime
)
```

```java
purchaseInfo.setSubsValidation(
    purchase.getOriginalJson(),
    purchase.getSignature(),
    purchase.getPurchaseToken(),
    purchase.getPurchaseTime()
);
```
</CodeGroup>

<Info>
`purchaseToken` can be `null` and `purchaseTime` can be `0`: in that case, the values are taken from `originalJson`.
</Info>

### Other providers
Google Play Billing is used by default. For purchases processed by another provider, attach that provider's validation data instead. This also marks the purchase as coming from that provider.

<CodeGroup synchronize={true}>
```kotlin
// Amazon Appstore: receipt ID and user ID
purchaseInfo.setAmazonValidation(receipt.receiptId, userData.userId)
// or the full Amazon IAP Receipt JSON
purchaseInfo.setAmazonValidation(receipt.toJSON().toString())

// Xsolla: order ID and optional user ID
purchaseInfo.setXsollaValidation(orderId, userId)
```

```java
// Amazon Appstore: receipt ID and user ID
purchaseInfo.setAmazonValidation(receipt.getReceiptId(), userData.getUserId());
// or the full Amazon IAP Receipt JSON
purchaseInfo.setAmazonValidation(receipt.toJSON().toString());

// Xsolla: order ID and optional user ID
purchaseInfo.setXsollaValidation(orderId, userId);
```
</CodeGroup>

<Note>
For Amazon Appstore purchases, you are responsible for supplying the price, currency, and quantity values (e.g. from your own product catalog) to ensure revenue is reported accurately.
</Note>

### 4. Report
With the purchase information prepared, `purchaseInfo` is ready to send:

<CodeGroup synchronize={true}>
```kotlin
CAS.reportPurchase(purchaseInfo)
```

```java
CAS.reportPurchase(purchaseInfo);
```
</CodeGroup>

## Automatic forwarding to Tenjin
Purchases reported through `CAS.reportPurchase(...)` can also be forwarded automatically to Tenjin Analytics, so you don't need a separate integration to get IAP revenue into Tenjin.
