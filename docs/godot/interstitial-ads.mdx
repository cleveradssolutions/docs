Interstitial ads are full-screen ads that cover the interface of their host app.
They're typically displayed at natural transition points in the flow of an app, such as between levels.
When an app shows an interstitial ad, the user has the choice to either tap on the ad and continue to its destination or close it and return to the app.

Interstitial ad management in Godot code is handled through the `CASInterstitial` object returned by `CASMobileAds.get_interstitial()`.
The interstitial ad is displayed by the native SDK on top of the game and is not a node of the scene tree.

## Load Ad
CAS provides an option to enable autoload to simplify your app logic.  
Before using the ad, you should decide whether to enable autoload, or manually manage each ad loading cycle in your code.

When autoload is enabled, a new ad will be automatically loaded after each display, and loading failures will trigger automatic retry attempts.

```gdscript
func _ready() -> void:
	var interstitial := CASMobileAds.get_interstitial()
	interstitial.loaded.connect(_on_interstitial_loaded)
	interstitial.failed_to_load.connect(_on_interstitial_failed_to_load)
	interstitial.autoload_enabled = true
	interstitial.load()


func _on_interstitial_loaded() -> void:
	# Called when an ad is successfully loaded.
	print("Loaded")


func _on_interstitial_failed_to_load(error: CASAdError) -> void:
	# Called when an ad load failed.
	print("Load failed: ", error.message)
```

Manual load mode is useful when you only need to show a single ad per game screen, and the screens change frequently.
When you want to manually control ad loading, set `autoload_enabled = false` and call `load()` each time you need a new ad.

Ad content may take some time to load. To ensure the ad displays instantly when needed, load the ad in advance.
You can use the `loaded` signal to be notified when the ad is ready for display.

<Info>
- Read more about `CASAdContentInfo` object in [Impression Level Data](godot/impression-level-data).  
- Read more about [CASAdError](godot/ad-errors) object. 
</Info>

## Preload several ads
To have an ad ready more often, keep several ads loaded at the same time, up to 4. 
`show()` presents the loaded ad with the highest revenue, and the shown ad loads a new one by itself.

```gdscript
var interstitial := CASMobileAds.get_interstitial()
interstitial.preload_count = 2 # [!code highlight]
print("Loaded ads: ", interstitial.get_loaded_count())
```

Preloaded ads always use autoload, so `load()` is not needed. 
`preload_count` can be set before `CASMobileAds.initialize()`, the ads start loading once the SDK is initialized.
Set `preload_count = 0` to return to a single ad.

## Show Ad
Interstitial ads should be displayed during natural pauses in the flow of an app. Between game levels is a good example, or after the user completes a task.
You can choose when to show the ad by calling `show()`:

```gdscript
func _ready() -> void:
	var interstitial := CASMobileAds.get_interstitial()
	interstitial.showed.connect(_on_interstitial_showed)
	interstitial.failed_to_show.connect(_on_interstitial_failed_to_show)
	interstitial.dismissed.connect(_on_interstitial_dismissed)


func show_interstitial() -> void:
	CASMobileAds.get_interstitial().show()


func _on_interstitial_showed() -> void:
	# Called when the ad showed the full screen content.
	print("Showed")


func _on_interstitial_failed_to_show(error: CASAdError) -> void:
	# Called when the ad failed to show full screen content.
	print("Failed to show: ", error.message)


func _on_interstitial_dismissed() -> void:
	# Called when the ad dismissed full screen content.
	print("Dismissed")
```

<Info>
When an error occurs during ad impression, only the `failed_to_show` signal is emitted.  
In this case, the `dismissed` signal will not be emitted since the impression is not considered successful.
</Info>

If the ad is not ready at that moment, the `failed_to_show` signal will be emitted with a reason.
You have the option to check `is_loaded()` if it's required by your app's logic.

```gdscript
if CASMobileAds.get_interstitial().is_loaded():
	# The ad is loaded here
	pass
```

### Auto Show Ad mode
CAS provides the option to automatically show a loaded ad when the user returns to the app.
To enable this behavior, set autoshow enabled:

```gdscript
CASMobileAds.get_interstitial().autoshow_enabled = true
```

## Game pause during the ad
While a fullscreen ad is on screen, the game is paused the same way as when the app becomes inactive: 
the main loop, rendering and game audio stop. 
Nodes receive `NOTIFICATION_APPLICATION_FOCUS_OUT` when the ad is shown and `NOTIFICATION_APPLICATION_FOCUS_IN` before the `dismissed` signal.

If your game opens a pause menu on focus loss, skip it during ads, or turn the pause off and handle the `showed` and `dismissed` signals yourself:

```gdscript
CASMobileAds.set_pause_game_during_ads(false)
```

The setting applies to interstitial, rewarded and app open ads. Enabled by default.

## Listening for the Ad Clicked
The `clicked` signal is emitted whenever a user clicks an ad. This can be useful for analytics, custom tracking, or UI reactions.

```gdscript
CASMobileAds.get_interstitial().clicked.connect(func():
	# Called when a click is recorded for an interstitial ad.
	pass)
```

## Minimum interval between impressions
The minimum interval between showing interstitial ads, in seconds.
Attempting to show a new interstitial ad before the interval has passed after the previous one was dismissed will emit the `failed_to_show` signal with `CASAdError.Code.NOT_PASSED_INTERVAL`.

```gdscript
CASMobileAds.get_interstitial().min_interval = 30 # seconds
```

To start the interval countdown again, for example after a rewarded or app open ad, call:

```gdscript
CASMobileAds.get_interstitial().restart_interval()
```

## Placement name
Set the `placement` property to group ad statistics by place in your game in the CAS dashboard. The name is applied before the ad load.

```gdscript
CASMobileAds.get_interstitial().placement = "level_complete"
```

## Mute Ad sounds
Indicates if the application’s audio is muted. Affects initial mute state for fullscreen ads. Use this method only if your application has its own volume controls (e.g., custom music or sound effect muting).

```gdscript
CASMobileAds.set_ad_sounds_muted(true)
```

Not muted by default.

## Release ad resource
Be sure to release ad resources when no longer needed. The ad options are kept, and the next `load()` creates a new ad.

```gdscript
CASMobileAds.get_interstitial().destroy()
```

## Some best practices
#### Consider whether interstitial ads are the right type of ad for your app.
Interstitial ads work best in apps with natural transition points. The conclusion of a task within an app, like sharing an image or completing a game level, creates such a point. Because the user is expecting a break in the action, it's easy to present an interstitial ad without disrupting their experience. Make sure you consider at which points in your app's workflow you'll display interstitial ads and how the user is likely to respond.

#### Allow for adequate loading time.
Just as it's important to make sure you display interstitial ads at an appropriate time, it's also important to make sure the user doesn't have to wait for them to load. Loading the ad in advance by calling `load()` before you intend to call `show()` can ensure that your app has a fully loaded interstitial ad at the ready when the time comes to display one.

#### Don't flood the user with ads.
While increasing the frequency of interstitial ads in your app might seem like a great way to increase revenue, it can also degrade the user experience and lower clickthrough rates. Make sure that users aren't so frequently interrupted that they're no longer able to enjoy the use of your app.
